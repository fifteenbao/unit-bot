# 行业案例：扫地机器人 PLANS 价值工程

本案例说明如何把通用 PLANTS 框架应用到扫地机器人。下面的分类和数据口径是行业扩展，不能直接复制到泵、家电或其他产品。

## 7 桶成本框架

扫地机器人 BOM 可按以下 7 个桶组织。占比是早期估算的参考区间，实际项目应以拆解、报价和 Should Cost 结果校准：

| 桶 | 内容 | 参考占比 |
|---|---|---:|
| 算力与电子 | 主控、存储、电源、通信和 PCB | 约 11% |
| 感知系统 | 激光雷达、摄像头、传感器和避障组件 | 约 25% |
| 动力与驱动 | 风机、电机、轮组、齿轮和驱动板 | 约 11% |
| 清洁功能 | 滚刷、边刷、拖布、尘盒和水路 | 约 20% |
| 基站系统 | 集尘、清洗、烘干、水箱和基站结构 | 约 17% |
| 能源系统 | 电池、充电和 BMS | 约 3% |
| 整机结构 CMF | 外壳、底盘、装饰件、紧固件和表面处理 | 约 13% |

这些桶用于拆解成本、功能价值矩阵和降本优先级排序。它们不是通用 PLANS 的固定组成部分。

## 行业专用数据和工具

- `data/products/`：扫地机器人规格、品牌和型号映射；
- `data/teardowns/`：拆机档案与 FCC OCR 结果；
- `data/lib/components_lib.csv`：标准件价格；
- `data/lib/materials.csv`、`processes.csv`、`molds.csv`、`tooling.csv`：Should Cost 输入；
- `scripts/fetch_fcc.py`：FCC 文档检索和 PCB 芯片 OCR；
- `scripts/cost_mfg_bom.py`：制造 BOM 与 Should Cost 对比。

## 适用方式

先用通用项目建立产品配置和阶段依赖，再在 P·拆解、L·DFM 和 A·功能建模阶段注入上述 7 桶和行业数据。行业 agent 可以继续使用原 `agents/` 下的扫地机提示词，但输出应保留来源、时间、数量和币种口径。

## 边界

公开占比只能作为早期假设；芯片、光学、电池和成品模组不宜直接套用材料加加工模型。供应商报价、模具摊销、税费、运输和良率应按项目实际条件重新核算。
